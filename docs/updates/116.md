# Intent of the change

- Finish coding-harness audit coverage. OpenCode and Gemini CLI now match Codex, Claude Code,
  and Cursor.
- Make one `openbot plugin` command install Tilde MCP servers, Tilde skills, and native ChatKit
  audit emission for every supported harness.
- Keep audit fail-open. Tilde outage must not stop coding work.
- Fix native MCP config details found during completion: OpenCode global config path/schema;
  Gemini Streamable HTTP field.
- Restore Changesets status by removing release notes for removed `@tryopenbot/mobile` package.

# Architecture changes

```mermaid
flowchart LR
  O[OpenCode stable plugin hooks] --> C[openbot plugin audit]
  G[Gemini command hooks] --> C
  C --> A[Dedicated SDK normalizers]
  A --> S[@trytilde/sdk recorder]
  S --> K[Tilde ChatKit sessions, messages, tool executions]
  P[openbot plugin setup] --> M[Native MCP config]
  P --> L[Native skill directories]
  P --> O
  P --> G
```

- Core recorder gains `opencode` and `gemini-cli` source identities. Session lookup keys and tool
  execution IDs remain source-scoped and idempotent.
- `@trytilde/sdk-opencode` owns OpenCode payload normalization and the packaged, globally
  discoverable fail-open plugin.
- `@trytilde/sdk-gemini-cli` owns Gemini hook normalization. Hook command writes `{}` to stdout,
  as Gemini requires valid JSON there; errors go to stderr.
- OpenCode MCP writes remote definitions into `~/.config/opencode/opencode.json`. Gemini MCP writes
  `httpUrl` definitions into `~/.gemini/settings.json`. Existing fields survive merge.
- No API, protobuf, provider, deployment, auth, secret, browser, Electron, or client-runtime boundary
  changes.

# Summarized package changes

- `@trytilde/sdk`: add OpenCode and Gemini CLI to public coding-agent source union and display names.
- `@trytilde/sdk-opencode`: add prompt, assistant-text, and tool lifecycle adapters; ship native plugin.
- `@trytilde/sdk-gemini-cli`: add session, prompt, response, and terminal tool adapters.
- `openbot`: install and dispatch all five harness audit integrations; fix OpenCode and Gemini MCP
  documents; preserve Gemini settings while installing hooks.
- SDK release tooling: build, validate, pack, install, type-check, and execute both new packages in
  the external-consumer smoke test.
- Tests: cover native hook normalization, idempotent installers, native MCP schemas, and full
  OpenCode/Gemini prompt-to-ChatKit HTTP request paths.
- Documentation: amend ADR-0030 and package/CLI READMEs. Add a Changeset for public behavior.
- Release hygiene: remove orphaned mobile-only Changesets and deleted-package references. Release
  plan validation works again.

# Critical to apply to forks

yes — forks using OpenCode or Gemini CLI must rerun `openbot plugin --cli opencode` or
`openbot plugin --cli gemini` after updating. This installs native audit hooks and rewrites selected
Tilde MCP servers using each harness's valid current schema. Forks importing SDKs directly may adopt
`@trytilde/sdk-opencode` or `@trytilde/sdk-gemini-cli`; existing Codex, Claude Code, Cursor, and
Vercel AI SDK integrations do not require code changes. No environment variable, secret, database,
provider, or deployment migration is required.
