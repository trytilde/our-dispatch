# Intent of the change

Stop the trusted remote runtime from resetting its deployed checkout through a nested Code Storage reconciliation.

# Architecture changes

```mermaid
flowchart LR
    Outer[Production deploy] -->|scoped source credential| Materialize[Materialize trusted runtime]
    Materialize --> Inner[Inner development lifecycle]
    Inner --> Local[Local Git provider]
```

The outer deployment still uses Code Storage once to materialize source. Code Storage variables are not copied into the inner runtime environment, where the local Git provider owns ongoing development state.

# Summarized package changes

- `@tryopenbot/agent-service-provider`: omit every `CODE_STORAGE_*` value from the remote environment while retaining the credential in the one-shot reconciliation input.
- Tests: prove the environment file excludes the repository token while the outer source script still receives it.
- Changesets: patch the fixed OpenBot package group.

# Critical to apply to forks

yes — forks using the trusted exe.dev runtime should update and redeploy. This prevents the inner lifecycle from overwriting the materialized checkout or failing startup when an external repository was renamed. No environment variable, credential, or state migration is required.
