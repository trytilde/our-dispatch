# PR 89: Explicit fork-only upstream markers

## Intent of the change

- Forks need a visible way to keep private or product-specific blocks out of reusable upstream contributions.
- The upstream contribution workflow now defines exact, balanced markers and requires a concrete reason for every exclusion.

## Workflow changes

- Search for `DO NOT UPSTREAM` before separating a contribution.
- Use language-valid comments with one opening token, one non-empty reason, and one closing token.
- Mark complete commentable files from first code to last code.
- Name uncommentable generated or data files from their nearest owning source.
- Reject nested, ambiguous, unbalanced, or accidentally included exclusions during final diff review.
